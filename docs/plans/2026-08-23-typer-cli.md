# Rebuild the config CLI on Typer: inline values, apply, export

Issue #194, first substantive issue of the #265 CLI chain.
Deviations, resolutions and discoveries land in the companion
`2026-08-23-typer-cli-implementation.md`, one section per milestone,
appended in the change that ticks the milestone.

## Goal

Replace the config CLI's ~800 lines of argparse machinery with a
Typer argument layer, add inline `key=value` writes beside `-f`,
add `config apply` (one document, dependency-ordered, refused
whole) and `config export` (the apply-able round trip), and give
the CLI its documentation home in `docs/reference/cli.md` with a
generated command reference under the existing drift discipline.
The valuable halves of `cli.py` (rendering, refusal sentences,
transport policy, the acts table) carry over; the parser subclass,
the hand-rolled subcommand tree and the manual dispatch wiring go.

## The issue's decisions, restated

- Typer for the argument layer; rendering, refusals and safety
  checks move unchanged; expected saving is a few hundred lines and
  lower friction per new subcommand.
- `set` accepts `key=value` pairs assembling the same fragment the
  YAML would, validated by the same models on the same write path;
  dotted keys nest, values parse as YAML scalars; `-f` stays, the
  two forms are alternatives for one command.
- `config apply -f setup.yaml`: one document, any number of
  entities, applied through the existing write path in dependency
  order, idempotent, refused whole on an unresolvable reference
  with the same sentences a single write earns.
- `config export`: the current store as an apply-able document, and
  per-entity; export is the writable projection, `show` the display
  one, per #192's read-modify-write contract; secrets never travel
  (env name or stored marker), `set-secret` stays the only door.
- `docs/reference/cli.md`: hand-written head (installation, remote
  use, `--local` break-glass), generated command reference under
  the drift checks.
- Pre-release: nothing owed to the current grammar; what survives
  does so on merit. The docgen no-database property survives.
  `reload` stays #191's verb, `diff` stays #193's reserved seat.
  OpenAPI-generated clients stay out of scope.

## What changed under the issue since it was written

## Decisions

### 1. The rebuild happens in place; #223 packages it afterward

Two ratified texts pull apart. The 2026-08-20 comment on this
issue says the Typer layer "should be built in that standalone
package directly rather than inside the server and moved later".
The #265 tracking issue, written 2026-08-23 and the operative
sequencing, says the opposite order: "#223 (standalone CLI) after
#194. It packages the rebuilt CLI, not the old one", with #223
still carrying the layout decisions (in-repo workspace member
versus separate repo, generated versus drift-checked shapes).

This plan follows #265, for three reasons. It is the newer
decision. Building in a standalone package now would need #223's
undecided layout first, inverting the ratified order. And the
grammar cannot move wholesale anyway: `--local` and the four
break-glass commands stay in the server package by #223's own
terms, so a package-first build would split one grammar across two
packages in the same change that rebuilds it. What this plan owes
the 2026-08-20 comment instead is extraction cleanliness: the
Typer app and the acts keep their strict client shape (HTTP,
rendering, no store import outside the `--local` arms), so #223's
move is a relocation, not an untangling. Recorded here so the plan
review and Rafael can veto the reading.

### 2. Typer joins the runtime dependencies; the boundary is ours

`typer` becomes a direct dependency (click is already in the tree
transitively via uvicorn). The app runs with
`standalone_mode=False` always: Click's own error path prints and
exits 2, and this CLI's contract is a ConfigError sentence on
stderr and exit 1, with `--help` leaving through exit 0.

The usage-error boundary adopts the stricter sibling shape
(`conversations/cli.py`'s marker table plus a deliberately vague
fallback) rather than porting `_usage_problem`'s narrow one. That
closes a pre-existing hole the census surfaced: today's config
grammar passes argparse's `invalid choice: 'x'` through verbatim,
echoing the typed word, while every sibling grammar refuses to.
Click's `UsageError` subclasses (NoSuchOption with its
did-you-mean, BadParameter quoting the value) are translated by
CLASS to fixed sentences, never by their text. The
secret-never-an-argument sentence stays on the
unrecognized-arguments shape. This is a recorded strengthening in
the changelog, and the grammar suite grows a planted-secret case
per usage-error shape.

Two argparse behaviors are load-bearing pins and must survive the
library change exactly:

- `--config`, `--api-url` and `--local` are accepted both before
  and after the subcommand, and a pre-command value is not
  clobbered by the command's absent one (today's
  `default=argparse.SUPPRESS` dance). Shape: the Typer root
  callback holds the three options; each command declares its own
  copies defaulting to an UNSET sentinel; resolution merges
  per-option, command-position winning only when given. Pinned by
  the existing `--local`-first cases across the local suite.
- `cli.main(argv: Sequence[str] | None) -> int` and
  `cli.build_client` keep their exact signatures and module
  positions: `main.py`'s word dispatch and every acceptance
  suite's monkeypatch depend on them, and neither changes.

`conversations/cli.py`, `events_cli.py`, `doctor.py` and
`main.py`'s own parser stay argparse: they are three small stable
grammars, and this issue buys Typer where the entity count grows,
not everywhere. The repository carrying two argument libraries is
recorded as the accepted cost.

### 3. The grammar keeps every spelling a committed artifact pins

Four command spellings are baked into shipped event messages and
the committed `events.md`: `config reload`, `config add-device`,
`config bind-device`, `config ota-url`. Two more live in write
notices and OpenAPI bytes (`config set`, `config set-secret`,
`config show device`). The redesign freedom is real but these
spellings stay; the pre-release license is for shapes that pin
nothing, and none of these earns a rename worth moving three
artifacts for. The grammar therefore keeps its verb set and
positional shapes; what changes is the machinery underneath, the
usage sentences (decision 2), and the additions (`key=value`,
`apply`, `export`).

### 4. Inline values assemble the fragment, and nothing else

`set <kind> [identity] key=value...`: each pair splits on the
first `=`, the key splits on dots into nesting, the value parses
as a YAML scalar (`yaml.safe_load` of the value string alone, so
`true`, `8`, `null` and quoted strings behave as in a fragment).
The assembled mapping enters the exact path a `-f` fragment
enters: `check_transportable`, the same PUT, the repository's
validation, the same acknowledgement. `-f` and pairs are
exclusive; neither given is the missing-argument usage error. Keys
colliding after nesting (`a.b=1 a=2`) are refused with a fixed
sentence naming neither. The help text for `set` carries the
warning that a secret is never a `key=value` argument (the store
already refuses plaintext secrets in fragments by key shape, and
that refusal covers this path unchanged; what the help adds is
the shell-history reason). The `fragment_help` epilogs from docgen
stay on the `set` commands.

### 5. `local_ok` becomes declarative, closing the recorded hole

Today a command joins the break-glass subset by an imperative
`set_defaults(local_ok=True)`, and
`test_config_cli_local.py:249-253` records that its differential
MUTATIONS list is held complete by review alone. In the Typer
layer, break-glass membership is a fact on the command
registration (one table of command factories carrying
`local_ok`), and a new test derives the expected MUTATIONS
coverage from that table, so a future `local_ok=True` command
that skips the differential fails a test instead of a review. The
differential acknowledgement pin itself
(`test_a_local_write_acknowledges_what_the_api_acknowledges`) and
its wording sibling carry over unchanged in meaning.

### 6. `apply` is a repository verb served by the API

The refused-whole bound decides the architecture: a CLI-side loop
of PUTs cannot refuse a document whole, because the store
validates references per write inside per-write transactions, and
stopping at the first refusal leaves the store half-applied. So
apply lands where the transaction is:

- `ConfigStore.apply(document)` cannot be a loop over the existing
  write internals: `_write` opens its own transaction and
  `_persist` runs `_refuse_unresolved` after each entity, so
  composing them either nests transactions or rejects intermediate
  states a complete document would resolve. The write path
  therefore refactors into transaction-neutral phases that single
  writes and apply share: parse and per-kind checks outside the
  lock where possible; one transaction; markers resolved against
  one snapshot; every incoming entity staged into one candidate
  domain state; `check_references` run ONCE against that final
  state; then all rows persisted. A single `set` becomes the
  one-entity case of the same phases, so there is one write path,
  not two. Refusals aggregate into one ConfigError whose lines are
  the same sentences the single writes earn; any refusal rolls
  back everything.
- `POST /apply` serves it (RawBody, unread by FastAPI, like every
  write); the answer lists per-entity outcomes (`wrote` or
  `unchanged`) and one combined notice set. The OpenAPI document
  moves, deliberately, regenerated under its byte pin, and the
  admin UI (#129) inherits a batch verb for free.
- `vinga-server config apply -f setup.yaml` posts it. Apply is not
  in the `--local` recovery subset (the subset stays the four
  commands; recovery does not need batches).

The document is a PARTIAL DomainConfig-shaped document: top-level
keys are the `DOMAIN_KEYS` sections, entity bodies exactly the
fragments `set` takes, and the two settings in their DOMAIN shape,
not their route-body shape: `devices` as `mac: [agents]` (the
route's `{agents: [...]}` is an adapter concern) and
`default_agent` as a scalar or an explicit null. Apply adapts
each settings entry onto the existing bind-device,
set-default-agent and clear-default-agent write semantics.

Omission is additive, stated as the rule: a section or entry the
document does not mention is untouched; an empty mapping adds
nothing; an explicit `default_agent: null` clears the setting,
and its absence leaves it alone. Apply never deletes: pruning a
store down to a document is a different verb with different
stakes (secret deletion among them), deliberately not built here,
and `cli.md` says so beside apply.

Idempotence is comparison, not blind rewrite: for each entity the
store compares the incoming body against the stored one through
the same write-shaped projection reads use (masks resolving to
keep-stored per #192's marker), and an equal body is reported
`unchanged` with no write and no notice. The same file twice is
therefore a no-op by construction.

The dependency order becomes data for the first time:
`APPLY_ORDER` beside the descriptors (providers, mcp-servers,
prompt-fragments, agent-defaults, agents, devices,
default-agent), with a test that plants one cross-reference per
edge `check_references` enforces and asserts the order satisfies
it, so the list and the checker cannot drift apart silently.

### 7. `export` is a CLI-side reshape of the reads that already exist

`config export` fetches the whole document read and the per-entity
envelopes the API already serves and emits the apply-shaped
document; `config export <kind> [identity]` emits one entity's
fragment. No new read endpoint: #207 made every read derive from
the descriptor registry and stay write-shaped, and #192's marker
made the display envelope the writable projection, so export is
assembly, not translation.

Secrets: the exported entity BODIES are exactly the read
envelopes' bodies, unchanged. An env reference is a body value
and travels as itself. A STORED secret is not in the body at all
(the envelope reports it separately, and the CLI has always
rendered it as a comment, because the mask is not a creatable
value); export keeps that: stored slots become YAML comment
annotations naming the slot and `set-secret`, never mask values
injected into bodies, since a mask in a CREATING write is
refused and would make apply-to-an-empty-store fail on its own
export. The supported reproduction sequence, documented in
`cli.md` and in the export header comment, is: apply the exported
entities, then run `set-secret` for each annotated slot. The
round-trip suite extends along exactly that order: seed a store
with env-referenced, stored-only and shadowing secrets; export;
apply onto a fresh store; run the annotated `set-secret`s; export
again; the two exports byte-identical.

### 8. `docs/reference/cli.md`, hand head and generated body

The hand-written head covers installation (docker exec shim,
`uvx`, `uv tool install`), remote use (`--api-url`/`VINGA_API_URL`
resolution order, the token variable, loopback-or-TLS), and
`--local` as break-glass. The generated half renders the command
reference from the Typer app: a new `config cli-reference` verb
prints it, the committed copy is byte-diffed by a docgen-suite
test and a CI step beside the four existing lanes, and the READMEs
link to the page instead of carrying partial copies.

Import weight: the generator imports the app module, which imports
the client machinery, so it is the second deliberate exception
beside `docgen.openapi()`. The child-interpreter pin
(`ALLOWED_IMPORTS` exact set) covers `schema` and `reference`
only and does not change; the no-database property is pinned for
the new verb the way it is for the other three (the `/nowhere`
database dir fixture), since rendering help opens nothing.

### 9. Presets and the documentation sweep

`examples/presets/local-stack.yaml` (faster-whisper ASR, an
openai-compatible local LLM, piper TTS, silero VAD, one agent,
defaults, a device-less bootstrap) and
`examples/presets/cloud-stack.yaml` (the cloud trio), each a
complete apply document with the secrets carried as env
references. The repository README's six heredocs collapse to one
`vinga config apply` line against the preset; the vinga-server
README's bootstrap block likewise; the manual order paragraphs
shrink to a sentence saying apply orders for you. The
examples-ownership docgen test learns the presets tier (files
owned by the apply document shape rather than one descriptor).
Every remaining `config ...` spelling site the census lists is
swept in the same milestone as the grammar piece that changes it,
and `config.example.yaml`'s comment block updates with the rest.

### 10. Milestones recut from #265's sketch, for releasability

#265 sketched "the Typer skeleton with read commands, then the
write and secret commands, then declarative apply". Cut that way,
M1 would ship a config CLI whose writes still parse under argparse
beside a Typer half, two co-equal grammars for one command group,
which is the shape the pipeline's own rule forbids merging. The
recut keeps #265's substance in three releasable milestones:

- M1 moves the WHOLE grammar to Typer mechanically: every command,
  current shapes, `-f` writes intact, the decision-2 boundary and
  strengthened usage sentences, `local_ok` declarative (decision
  5), suites migrated. Behavior deltas: usage sentences only.
- M2 adds inline `key=value` (decision 4) and the apply/export
  pair (decisions 6 and 7): the store verb, the route, the two
  commands, the round-trip extension. The OpenAPI artifact moves
  here.
- M3 is the documentation milestone: `cli.md` with its generated
  half and drift lane (decision 8), the presets, and the README
  and examples sweep (decision 9).

## Tests

survives except where a usage sentence deliberately changed
(decision 2's recorded list); the grammar suite grows the
per-shape planted-secret cases; the local suite's differential
pins carry; the SUPPRESS-equivalent both-positions behavior is
already exercised by the `--local`-first cases and must stay
green. M2: inline-value cases beside each fragment case (same

store in the acceptance suite, and the docgen ownership tier.
Inventories by tooling: the census's spelling-site list is the
sweep's checklist, re-grepped at review time.

## Risks

- **Click's error surface is wider than argparse's.** Unknown
  options carry did-you-mean suggestions, bad values quote
  themselves; any shape not translated by class leaks. Mitigation:
  the boundary translates by exception CLASS with a vague
  fallback, and the grammar suite plants a secret in every shape
  the boundary names.
- **The both-positions option merge is subtle.** The sentinel
  merge must reproduce SUPPRESS semantics exactly; the local
  suite's `--local`-first cases are the pin, and M1 does not merge
  until they pass unmodified.
- **`store.apply` under concurrent writers.** It rides the same
  single-transaction discipline every write rides (the busy
  timeout and the retryable 409); one transaction holding many
  writes holds the lock longer, which the route's read timeout
  already accommodates (the CLI's 30 s read against the 10 s busy
  bound); recorded in the route docstring.
- **Artifact churn.** Only the OpenAPI document and
  `domain-config.md` may move (M2's route; any registry `command`
  text if a spelling changes, which decision 3 forbids), plus the
  new `cli.md`; `events.md` must not move, and that is asserted at
  each milestone's drift run.

## Plan review round

External review of commit `e1661cb9`, 2026-08-23. Backend: codex
CLI 0.149.0, model `gpt-5.6-sol`, read-only sandbox, runtime
6m11s. Verdict as received: ready after the P1/P2 amendments.
Thirteen findings, seven P1; each amendment is its own commit with
a resolution note here. Findings 7 and 8 corrected the plan
author's own reading: #265's body carries, below its estimates
table, the live-uvicorn acceptance lane, the derived recipes and
the fileless quick start as work landing with this issue, and the
plan had been written from a truncated read.

1. **P1: the proposed store composition cannot provide one
   transaction and final-state validation.** `_write` opens its
   own transaction and `_persist` runs `_refuse_unresolved` after
   each entity, so calling the internals in order either nests
   transactions or rejects intermediate states.

   *Resolution* (this commit): decision 6 now requires the
   two-phase refactor: transaction-neutral preparation and
   persistence shared by single writes and apply, one transaction,
   markers against one snapshot, one candidate domain state, one
   `check_references` pass, then persistence; a single `set` is
   the one-entity case of the same phases.

2. **P1: the apply document contradicted the existing shapes for
   devices and the default agent.** Both are settings, not
   fragment entities: their write bodies are `{agents: [...]}` and
   `{name: ...}`, while the domain document holds `mac: [agents]`
   and a scalar-or-null; omission semantics were unstated.

   *Resolution* (this commit): the document is a partial
   DomainConfig-shaped one with the settings in their domain
   shapes and adapters onto the existing settings write semantics;
   omission is additive, an explicit `default_agent: null` clears,
   and apply never deletes, stated in `cli.md` beside the verb.

3. **P1: export described stored secrets incorrectly and its
   fresh-store test skipped the real bootstrap problem.** A stored
   ciphertext is not a mask in the writable body; it is reported
   separately and rendered as a comment because the mask is not a
   creatable value, and apply-to-empty would fail on it while
   `set-secret` cannot run before the entity exists.

   *Resolution* (this commit): decision 7 keeps exported bodies
   identical to the read envelopes, renders stored slots as YAML
   comment annotations naming `set-secret`, and the documented
   reproduction order is apply-then-set-secret; the round-trip
   test follows that supported order over env-referenced,
   stored-only and shadowing secrets with no back-door seeding.

4. **P1: apply omitted API-side device housekeeping and cannot
   produce the promised notices from the store.** Device and
   default-agent notices depend on loaded agents and snapshot-only
   mode, which the store does not know, and the routes retire
   pending codes after a successful commit.

5. **P1: inline scalar parsing lacked the no-leak boundary and
   would accept non-scalars.** `yaml.safe_load` accepts lists and
   mappings, and an unhandled YAMLError can retain or print the
   submitted text.

6. **P1: the apply timeout argument was false for an unbounded
   batch.** Thirty seconds exceeds the lock wait but not the
   duration of an arbitrarily large transaction, recreating the
   unknown-write outcome the timeout rationale exists to avoid.

7. **P1: the live-server acceptance deliverable was absent.**
   #265 requires an integration suite booting real uvicorn and
   driving the rebuilt CLI's whole command inventory over the
   wire, refusal paths included; the plan tested presets only
   through the in-process runner.

8. **P2: M3 omitted the derived-recipes and fileless-quick-start
   deliverables.** #265 requires per-topic recipes DERIVED from
   the descriptor-owned example fragments and run against the live
   lane, a no-config-file boot verified, and the quick start
   rewritten; `config.deploy.example.sh` was unaccounted for.

9. **P2: existing fragment help does not meet the generated-help
   requirement.** `fragment_help` renders names and first
   sentences only, omitting types and defaults `docgen.default()`
   already computes.

10. **P2: `APPLY_ORDER` would duplicate `DOMAIN_KEYS`,** which is
    already documented as the write, read and creation order; a
    second structure is the drift the design guide forbids, and
    behavior does not belong in `entities.py`.

11. **P2: the claimed global-option coverage does not exist.**
    Only `--local` is tested after a leaf command; no test proves
    a command-position value beats a root-position one.

12. **P2: the mixed hand-written/generated reference had no
    implementable drift protocol,** and the renderer's owner was
    left as "docgen.py or cli.py".

13. **P2: the file inventory contradicted itself and omitted the
    lock.** `config.example.yaml` was listed both changed and
    unchanged, and adding typer moves `uv.lock` because CI
    installs `--frozen`.
