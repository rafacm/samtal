# Split tools/mcp.py and seat one ToolSource under the three sources

## Goal

Implement issue #140: `tools/mcp.py` is 2,338 lines at plan time
(the issue's post-#122 figure was 1,894; the #155 emitter migration
and reload-token work grew it further), bundling at least twelve
responsibilities across two classes, and the runtime stitches three
tool sources with four call conventions. Split the file along its
real seams as a package that keeps its module identity, put one
`ToolSource` interface under builtins, device tools, and MCP tools,
type the status and reload surface the API consumes, and move the
import-time log-filter side effect to explicit setup, all under the
issue's no-behavior-change contract.

The companion implementation doc,
[`2026-08-17-mcp-split-implementation.md`](2026-08-17-mcp-split-implementation.md),
records what each milestone actually did, deviations, and
discoveries; a milestone with no deviations says so explicitly.

## The issue's decisions, restated

Settled by issue #140 and not re-litigated here:

1. **A `ToolSource` interface** (offer/snapshot for an agent,
   dispatch a call, resolve a timeout; exact shape in this plan)
   implemented by the builtin, device, and MCP sources; the
   pipeline's snapshot and dispatch become one loop over sources.
   `switch_agent`'s loop-ending special case stays in the runtime.
2. **`tools/mcp.py` splits by responsibility** (transport/manager,
   grant slice and shadowing, reload orchestration, status
   rendering; exact module boundaries in this plan). The status
   surface consumed by the API becomes typed instead of raw dicts,
   without changing the wire shape the API answers.
3. **The import-time log-filter side effect moves to explicit
   setup.**
4. **The MCP lifecycle events keep flowing through the split** (the
   #138/#155 machinery defines them; this issue keeps them).
5. **The device-side JSON-RPC layer stays its own transport**; only
   the duplicated result-decoding logic unifies.
6. **Per-tool grant semantics, shadowing rules, reload two-phase
   behavior, refusal sentences, and the #122 guidance capture
   behave identically.**

The no-behavior-change contract: all MCP unit and integration test
files pass, modified only where they pinned private members that no
longer exist; ported tests go through the new seams with equal or
stronger assertions; the reload integration proof and the
reflection/sanitization sentinel tests pass (see the contract
tension resolved below).

## Decisions this plan makes

### The split is a package that keeps the module's identity

`tools/mcp.py` becomes the package `samtal_server/tools/mcp/`,
whose `__init__.py` IS the module `samtal_server.tools.mcp`: it
constructs the one emitter (`events = ServerEvents(__name__)`, so
the channel string is unchanged by construction), re-exports every
public name and every constant the test surface imports (the 45+
names inventoried at M1), and holds nothing else. The retained
records' `logger` field, the five event-pin lines, the six
`MANAGER_LOGGER` filters, and #155's `SERVER_CHANNELS` literal are
all byte-identical without any of them being edited. The same
rule covers the ORDINARY prose records: every submodule logs
through the fixed package logger (`logging.getLogger(__package__)`
in submodules), never `__name__`, because tests filter non-event
records by the exact package name too; the rule is stated in the
package docstring.

The submodules, each under roughly 500 lines with one stated
responsibility:

- `transport.py`: `_resolve`, `_connect`, the stdio stderr sink,
  the SDK-logger quieting (as explicit setup, below), the
  connection-identity and failure-classification helpers
  (`_connection_identity`, `_reason`, `_carries`, `_down_reason`),
  and `_result_text` delegating to the unified decoder.
- `manager.py`: `McpServerManager`'s lifecycle and state machine
  (`start`/`stop`/`expect`/`same_as`/`_run`/`_became`/
  `ensure_reconnecting`/`call`/`_mark_down`) minus the prompt
  capture; the task-abandonment plumbing (`_abandoned`,
  `_abandon`, `_forget`, `_stopped`) moves here with it as
  module-level names (generic in shape, but inventing a shared
  utility module for one consumer is scope this plan declines).
- `prompts.py`: the 307-line #122 capture
  (`_capture`/`_discover`/`_listing`/`_bounded`/`_injectable`/
  `_rendered` and kin), taking the session and config it needs as
  arguments rather than reading manager internals, called by
  `manager.py` at the same points in `_run`.
- `slice.py`: `McpSlice`, `_allowed`, `_nothing_shipped`, and the
  shadowing helper `_shadowed`.
- `reload.py`: `McpReload`, the refusal sentences and tokens,
  `_refusal`, and the two-phase orchestration
  (`reload`/`_preparation`/`_read`/`_prepared`/`_apply` and kin)
  as functions over the registry, keeping the `config.loader`
  exception-type contract exactly (the types ARE the HTTP statuses
  409/422/500, stated in its docstring).
- `registry.py`: `McpServers` (construction, `build`, the egress
  check via `_managers_for`, `tools_for`/`tools_for_agent`,
  `guidance_for_agent`, `_reachable`, `owner_of`, `call`,
  `timeout_for`, `status`), delegating reload to `reload.py`.

Emit sites move into `manager.py` (six) and `registry.py`/
`reload.py` (two), which is what the next decision makes lawful.

### #155's channel-ownership rule gains the package form

The conformance suite's rule that an emitting module literally
contains `ServerEvents(__name__)` was written when every subsystem
was one module. The split makes the honest general rule explicit:
a CHANNEL is owned by a module or by a package, and a submodule of
an owning package may import its package's emitter (`from . import
events`). The conformance test gains that second accepted form
(the emitter must still be constructed with `ServerEvents(__name__)`
in the owning `__init__`, and a submodule may only import the
emitter of its own package, checked by path), the WALKER's channel
resolution updates with it (an emit site in a submodule that
imports its own package's emitter is recorded under the owning
package's channel, and package `__init__` paths normalize to the
package name, not `.__init__`), the channel-set equality keeps
`samtal_server.tools.mcp` as one channel, and the sidecar's eight
source identities update to the new module-qualified paths, which
is the deliberate, recorded update that map exists for. Planted
accepted and rejected cases cover the ownership form, the walker's
channel attribution, and the path normalization alike. The registry's `EventVariant`s are untouched:
the channel value they declare does not change. This is machinery
amendment, not surface change: the retained log is byte-identical,
proven by `test_server_event_pins.py` passing unmodified.

### The contract tension, resolved: one sentinel line moves

The issue demands the reflection sentinels pass unmodified AND
permits modification where tests pinned members that moved. Those
conflict for exactly one line: the monkeypatch target
`mcp_module.stdio_client` relocates with `_connect` to
`transport.py`. Resolution: the general clause governs the
specific; that one patch line (and its `spawning =` capture) is
updated to target `transport.stdio_client`, everything else in the
file byte-unchanged, and the test still fails loudly if the patch
misses (it asserts exactly one sink was spawned), so its strength
is intact. Recorded as the contract's one exercised allowance; the
reload integration proof needs nothing (it is fully black-box, no
private reach, no logger pin).

### The `ToolSource` seam lives in `tools/`, shaped by what exists

`samtal_server/tools/source.py`, importing `providers.ToolDef` and
stdlib only, so the pipeline imports downward as it already does:

- `snapshot(agent) -> Sequence[ToolDef]`: what this source offers
  the agent now.
- `owns(claim) -> bool`: is this call mine, judged from the
  per-call CLAIM the runtime already produces and reserves (the
  `_classified` outcome carrying the call, its source token, and
  the reserved MCP entry), answered the way each source answers
  today: the builtin source by name membership, the device source
  by scanning the live `device_tools()` exactly as `_dispatch`
  does now, the MCP source by the claim's reserved entry.
- `dispatch(claim, agent) -> tuple[str, bool]`: execute against
  the SAME claim, so the MCP source calls
  `McpServers.call(..., expected=claim.entry)` and a reload can no
  more reroute an in-flight call than it can today (the
  reservation semantics `test_session_tools.py` pins); the builtin
  `remember`'s bare `str` gains its `, False` inside the builtin
  source, and the no-memory `remember` case is the builtin
  source's own answer: it owns the name and returns the exact
  unknown-tool sentence, byte-identical, so "names, not outcomes"
  holds without a runtime fallthrough.
- `timeout_for(claim) -> float`: the MCP source answers
  `manager.tool_timeout_s` for the claim's reserved entry, the
  others `DEFAULT_TOOL_TIMEOUT_S`, which is today's fork expressed
  as data over the same claim dispatch uses.

Three implementations: `BuiltinTools` (wrapping the free functions
in `tools/builtin.py`, which stay free functions; the source holds
the agent list and memory reference the snapshot guards read),
`DeviceTools` (wrapping the `DeviceOutput` methods), and
`McpServers` itself (implementing the protocol directly; its
existing methods already match). The pipeline's `_tool_snapshot`
and `_dispatch` become one loop over `self._sources` in a fixed
order (builtin, device, mcp: today's precedence), the malformed-
arguments branch and the truly-unowned unknown-tool branch stay in
the runtime (no source claims them), `switch_agent`'s loop-ending
case stays in
`_run_tools`/`_refuse_handover` untouched, and the `tool_call`
event's `source` field keeps coming from `tool_source` (names, not
outcomes) so the classification surface is unchanged. Deliberately
inherited, not changed: the device source re-scans `device_tools()`
at dispatch (the edge case of a device list changing between
classification and dispatch behaves exactly as today), and the MCP
source's routing off the classified entry keeps its
re-resolution-is-wrong rationale, moved with the code.

### The status and reload surface, typed without wire change

`McpServers.status()` KEEPS its dictionary shape (the reflection
sentinel indexes those dicts and `json.dumps`es the mapping, and
every internal consumer reads them; typing that method would force
edits the contract forbids). The typed surface the issue demands
is the API-facing adapter: `typed_status()` on the registry
model-validates the same dicts into `dict[str, McpServerStatus]`,
and the reload path returns `McpReloadResult` built in
`reload.py` where the knowledge lives (the hand-flattening leaves
`api.py`), byte-identical on the wire since those models already
validate these shapes at serialization. The API's two
`Annotated[Any]` dependencies become a typed Protocol,
`McpStatusSource` (the typed status and the reload callable's
shape), living in `config/responses.py` beside the models it
returns, importing typing and the models only, which respects the
recorded constraint that rendering the OpenAPI document loads
neither the MCP SDK nor the provider layer. The OpenAPI document
must regenerate byte-identical (the drift check is the proof).

### The result decoders unify around one placeholder

The shared piece is extracted to where both sides can reach it
(`protocol/mcp.py` already owns the wire-shape logic and imports
nothing of tools/): one function producing the placeholder
sentence and the join over a normalized `(type, text)` sequence.
`parse_tool_result` keeps its dict-tolerant branches and
`tuple[str, bool]` shape; `transport.py`'s `_result_text` keeps
its typed-content iteration and `str` shape; the five behavioral
differences the inventory catalogued are preserved because they
are load-bearing for their respective wire layers. The one pinned
sentence has one home.

### The log quieting becomes explicit setup, called where it must be

`transport.quiet_sdk_loggers()`: idempotent, applying the same
filters and the same `propagate = False` with the same rationale
comment. Called at the public MANAGER START boundary (the first
thing `McpServerManager.start` does), because several suites,
including the HTTP no-leak proof, construct and start managers
directly without `McpServers.build`; `build` calling it too costs
nothing by idempotence. It is therefore in force before any
connection on every path, which is what the reflection sentinel
actually proves (a real subprocess connect leaking nothing). Import-time behavior is otherwise unchanged; the module
no longer mutates global logging state on import, which is the
issue's requirement.

### What is deliberately not done

- No behavior change anywhere: sentences, tokens, grants,
  shadowing, reload semantics, capture bounds all byte-identical.
- The device re-derivation edge case and the no-memory `remember`
  fallthrough are inherited exactly (recorded above), not fixed.
- No shared "async utilities" module for the abandonment plumbing:
  one consumer, one home.
- `McpServers({})` positional construction keeps working (the
  support fakes and boundary suite use it).
- The events registry's variants, the README index, and the
  generated events reference are untouched (channel and shapes
  unchanged); only the conformance suite's rule and sidecar move,
  as #155 designed them to when a surface moves deliberately.
- `protocol/mcp.py` and `tools/device.py` stay their own layer.

## Risks and mitigations

- **The channel machinery amendment breaks #155's guarantees.**
  The amendment narrows nothing: the owning-package form still
  requires a literal `ServerEvents(__name__)` in the `__init__`
  whose `__name__` equals the declared channel, and submodules may
  import only their own package's emitter; planted-source proofs
  cover both the accepted and the rejected shapes.
- **The atomic-swap contract breaks across the reload/registry
  boundary.** `_apply` moves whole into `reload.py` and mutates
  the registry through one method that performs the five
  assignments with no await, keeping the docstring contract in one
  place; the reload suite's existing tests are the pin.
- **Re-export drift**: a constant the `__init__` forgets breaks a
  test import loudly (good), and M1's port table is built from the
  inventory's import list, not from discovery by failure.
- **The manager/prompts split changes capture timing.**
  `prompts.py` is called at the same `_run` points with the same
  arguments; the prompts suite's 800 lines are the pin, and its
  two monkeypatched timeouts move with their constants.
- **Scope creep via review.** The bar paragraph rides every
  review prompt, as it has since #155.

## Plan review round

External review of commit f3971aa by codex 0.147.0 (model
gpt-5.6-sol), 2026-08-17, under the maintainer's sized bar. Seven
findings (2 P1), verdict ready after the amendments; as received,
condensed but faithful, each with its resolution:

1. **P1: `ToolSource` drops state routing behavior requires.** The
   reserved `ToolInvocation.entry` reaches both timeout selection
   and `McpServers.call(..., expected)` so a reload cannot reroute
   an in-flight call (pinned by `test_session_tools.py:352-395`),
   and the proposed shape has no way to pass it; nor can the
   unknown-tool branch stay in the runtime while
   `BuiltinTools.owns("remember")` is true without memory.

   *Resolution*: accepted. The protocol threads a per-call CLAIM:
   the runtime's reservation (`_classified`'s outcome, carrying
   the reserved entry) is handed unchanged to `owns`, `dispatch`,
   and `timeout_for` as the claim argument, so the MCP source
   routes and bounds by exactly the reserved entry as today; and
   the no-memory `remember` case is acknowledged as the builtin
   source returning the exact unknown-tool result (the sentence is
   the source's answer, not a runtime fallthrough), byte-identical
   output, with the classification surface unchanged. Amended in
   the seam section.

2. **P1: typed status models cannot leave the reflection sentinel
   otherwise unchanged.** The sentinel indexes status values as
   dicts and `json.dumps`es the mapping; pydantic models are
   neither.

   *Resolution*: accepted, second option. `McpServers.status()`
   stays dictionary-shaped (the sentinel and every internal
   consumer untouched), and the typed surface the issue demands is
   the API-facing adapter: the `McpStatusSource` Protocol's
   `status()` returns `dict[str, McpServerStatus]` built by a thin
   typed view (`typed_status()` on the registry, model-validating
   the dicts), which is what the API dependency consumes and what
   retires the `Annotated[Any]`s. Wire shape identical; the
   sentinel keeps its single `stdio_client` line as the only
   touch. Amended in the typed-surface section.

3. **P2: the conformance amendment does not update channel
   inference.** The walker assigns channels from physical module
   names and normalizes `__init__` naively.

   *Resolution*: accepted. The amendment includes the walker's
   channel resolution (a submodule importing its own package's
   emitter is recorded under the owning package's channel) and
   `__init__` path normalization, with planted accepted and
   rejected cases for both, alongside the ownership assertion.
   Amended in the machinery section.

4. **P2: the ordinary MCP loggers would drift to submodule
   names.** Non-event records use `logging.getLogger(__name__)`
   and tests filter them by the exact package name.

   *Resolution*: accepted. Every split module's ordinary logging
   uses the fixed package logger (`logging.getLogger(__package__)`
   in submodules), stated as a rule in the package docstring, so
   prose records keep `samtal_server.tools.mcp` byte-identically.
   Amended in the package section.

5. **P2: quieting only from `McpServers.build` misses direct
   manager paths.** Suites construct and start managers directly,
