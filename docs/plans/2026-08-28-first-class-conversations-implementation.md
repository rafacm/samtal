# First-class conversations: implementation

The companion to
[`2026-08-28-first-class-conversations.md`](2026-08-28-first-class-conversations.md),
one section per milestone, appended in the change that ticks the
milestone. It records deviations from the plan, resolutions of anything
the plan left open, and discoveries; a milestone with no deviations
says so explicitly.

## M1: sessions are sessions, conversations exist

PR #332.

### What landed

In the order the commits tell it: the runtime's snapshot first, then
the schema and the rows, then the refusal and its record, then the
events, then the two renamed surfaces, then the documents.

- **The owning snapshot.** `TurnRecord` gains `conversation` beside
  `agent`, both required and both stamped where the turn began.
  `TurnUnderway` carries the pair as its two leading fields and
  `record()` stamps them; its `agent` parameter is renamed `speaking`,
  because what it decides is the last leg of a split reply and not who
  the turn belongs to. `turns.agent` changes meaning with it, from the
  agent that finished the reply to the agent that owns the turn, and
  the handover pin in `test_session_record.py` moves deliberately.
- **Minting at the activation seam.** `PipelineRuntime` keeps a
  `dict[agent, conversation]`; `_activate_agent` mints a `uuid4().hex`
  on an agent's first activation in a session and reuses it on every
  later one. The id lives on `SessionEvents.conversation`, beside the
  active agent and for the same reason: both sides of the device
  boundary attribute records to it.
- **The re-cut baseline.** `1001_postgres_conversations` is deleted and
  `1002_conversation_threads` is the sole revision, autogenerated
  against the metadata and then reviewed. It carries the four existing
  tables with `turns.conversation` (text, not null) added, the
  `conversations` table, the dormant `conversation_milestones` table,
  and the five indexes the plan names.
- **`conversations/threads.py`,** the thread store: `Landing` and
  `landed()` for materialization, title derivation and activity;
  `title_of()` with `TITLE_CHARACTERS`; `Pruned` and `prune()` for the
  whole retention ruleset. Nothing in it opens a transaction; every
  function runs inside the caller's.
- **The writer delegating to it.** `_write` inserts the turn, its
  invocations, and then hands `threads.landed` one `Landing` per turn
  inside the same marker transaction, with the text switch already
  applied. `_prune` calls `threads.prune`; `store._delete_sessions`
  deletes. `ConversationsPruned` gains its `conversations` count and
  the writer keeps each session's device so a thread row can name it.
- **The stranded-database refusal.** `db.SUPERSEDED_REVISIONS`,
  `db.SUPERSEDED_REVISION` and `db._stranded` return, in the shape #243
  gave them and #283 deleted, with the conversations baseline as the
  closed set. The ADR gains its addendum and the changelog its two
  breaking entries.
- **The conversation on the events.** A `ConversationId` value type
  with a `conversation_id` syntax of its own, the field on the sixteen
  agent-bearing session declarations, `from_conversation` and
  `to_conversation` on `handover`, and the six `events/assembly.py`
  builders taking the thread beside the agent.
- **The rename.** The three GETs move to `/api/sessions*`, the response
  models to `SessionList`, `SessionSummary`, `SessionDetail`,
  `SessionTurn` and `SessionTurns`, and a turn response carries its
  `conversation`. `ToolInvocation` and `TurnLeg` keep their names.
- **The documents**: `docs/reference/events.md`,
  `docs/reference/api-openapi.json` and
  `docs/reference/conversations-schema.md` regenerated (the last
  through its generator's prose, which is the only way to correct a
  generated page), `docs/concepts.md`, `docs/glossary.md`,
  `vinga-server/README.md`, `CHANGELOG.md` and the command-spellings
  manifest.

### Deviations from the plan

Four, each with its reason.

1. **The baseline, the writer, `threads.py` and the retention ruleset
   land in one commit rather than several.** The plan describes them as
   separable pieces of one milestone. They are not separable into green
   commits: `turns.conversation` is not null, so the commit that adds
   the column is the commit that must write it; and the plan's own
   retention section requires the ruleset to land atomically with the
   rows, because session-age pruning and thread rows cannot coexist.
   Everything the plan lists that could be split off was: the runtime
   snapshot before, the refusal, the events, the rename and the
   documents after.

2. **A landing that cannot name its agent or its device materializes no
   thread row.** The plan makes `conversations.agent` and
   `conversations.device` not null and says nothing about a turn that
   has neither. `turns.agent` is nullable and `sessions.device` is
   nullable, so the writer can be handed one. The runtime activates an
   agent before it can produce a turn and a session knows its device
   before it can build a runtime, so this is a defect's shape rather
   than a configuration's; `threads.landed` therefore stores the turn
   and leaves the thread rowless, which is exactly the state a thread
   has before its first turn and which every reader already handles.
   The alternative, inserting a row with an invented agent, would put a
   lie in a column that is about to be the resume key.

3. **The turn responses gained `conversation` with the column rather
   than with the rename.** The plan lists it under the rename. The
   route reads every `turns` column but `session`, so the field appears
   in the response the moment the column exists; carrying it as a
   separate commit would have meant a red one in between.

4. **`vinga-server/README.md` moved in this milestone.** The plan's
   documentation footprint for M1 does not name it. It described the
   store as sessions and turns, its retention as taking whole sessions,
   and the API namespace as `/api/conversations`, all three of which
   this milestone falsifies, and a README that describes a server this
   repository does not build is the thing the concepts page's own
   authority rule forbids.

### Discoveries

- **The reset path was exercised for real, unplanned.** The unit lane's
  boot suites reach the compose instance's `vinga` database rather than
  the per-worker lane database, because `ServerConfig` bakes
  `DatabaseConfig`'s defaults into its compiled schema at import time
  and the conftest's model patch cannot reach them. That database was
  stamped at the deleted revision from before this branch, so the
  suites met the new refusal for real. The fix was the documented one,
  run exactly as the ADR addendum states it: drop and recreate the
  database, rerun `deploy/postgres-init.sql`, boot. It worked, which is
  what "tested" means in that addendum. The lane leak itself is
  pre-existing and out of scope here; it is worth an issue of its own,
  because a boot suite that writes to a developer's `vinga` database is
  a suite that can be affected by whatever else has touched it.

- **Retention's tests had to grow a second clock.** With the unit as
  the thread, a session stamped two hundred days ago whose turns landed
  "now" holds a live conversation, which is the case the ruleset exists
  to protect rather than the case an old-session test wants. So the
  retention suite, the store's tombstone case and the event-baseline
  prune driver all seed through a store whose own clock is old, which
  is the only difference between a synthetic old thread and a real one.

- **`ConversationsPruned` needed two counts, not one renamed.** The
  rules delete threads and session records for different reasons and in
  different quantities, and an operator reading one number could not
  tell which. Both are carried; the milestone-count and the event-count
  tables in `test_event_baseline.py` move with them.
