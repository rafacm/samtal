# Architecture diagrams

Three files here are not diagrams. [`principles.md`](principles.md) holds vinga's product promises and the architecture principles that keep them, each with an example and a counterexample, to be read before designing a feature or deciding direction. [`design-guide.md`](design-guide.md) holds the design method those principles are implemented with: the vocabulary of depth, seams and adapters defined against this codebase, the deletion test, and four merged changes worked through as examples. Principles say where the boundaries are; the guide says what a module inside one looks like, and when the two pull apart the principles win. [`cli-guide.md`](cli-guide.md) does the same job one layer out, for the surface an operator types at: the noun-verb grammar and why it is that way, the practices a command is held to with an example and a counterexample apiece, and the audit of four published CLI guides that produced them.

The diagrams live under [`diagrams/`](diagrams/README.md), a directory per authoring tool, indexed there by the question each one answers.
