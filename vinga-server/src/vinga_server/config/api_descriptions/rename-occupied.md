Either the new name is already taken somewhere this rename would write, by an agent, by remembered facts or by recorded conversation threads, or the configuration database's write lock is held by another request. A rename may never merge two pasts into one, which is why an occupied destination is refused rather than merged. Nothing was changed and neither name is quoted back. The held lock clears on its own and the request can be made again; an occupied destination does not clear, and what clears it is choosing another name or taking away what is filed under this one.
